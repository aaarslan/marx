# Current limitations

The current targets are native Windows 11 x64 with WebView2 and macOS Apple Silicon with WKWebView, using Wails 3.1.0 and Go 1.27.3. Native macOS acceptance is current. The November 1 Windows run repeated Wails 3.1.0 synthetic acceptance, race checks and isolated installation, with a limited production GUI pass. The complete earlier manual checklist was not repeated. Earlier Electron verification records are historical. See [the current verification report](wails-migration.md).

## Integration boundaries

All scan acceptance used a synthetic Go CLI and disposable data. No live Checkmarx tenant, real source upload, organization proxy/certificate setup or live triage is claimed. Use the organization's approved CLI; capability help checks cannot prove tenant compatibility. Desktop notifications were removed at the user's request after visible delivery could not be established. Scan completion, diagnostics and result navigation remain available in the application. No notification delivery or click-through success is claimed.

A user-assisted physical Explorer folder drop and an installed VS Code link launch were verified with disposable source. Cursor and full screen-reader behavior remain unqualified. Local paths with spaces, Unicode, parentheses, brackets and mixed separators have coverage. A real loopback SMB/UNC source read and scan passed; remote NAS authentication, network failures and latency remain outside that check.

The Wails child-frame/native-bridge limitation remains disclosed in [SECURITY.md](../SECURITY.md). Frames and remote resources are blocked. The installer is unsigned, requires WebView2, and targets x64 only. macOS has a locally verified ad hoc signed app bundle, without notarization or distribution qualification. Linux and Intel macOS are outside this verification.

## Evidence and workflow bounds

- All findings within the 64 MiB report limit are imported, including the tested 5,051-finding case. Incomplete reports remain marked truncated; unsupported scanners and unknown severities remain visible. The interface keeps the full normalized scan in memory and pages displayed rows.
- A passing remediation verification requires complete, compatible evidence, stable finding identities, successful engine coverage and effective server configuration. Ordinary CLI scan metadata does not establish all of that evidence. Missing findings alone cannot prove a fix. Original session evidence is pinned separately from refreshed results.
- Source fingerprints cover bounded local files, not an immutable CLI upload archive. Source may change during packaging/upload; source freshness is advisory and this gap prevents conclusive verification.
- CLI connection identity hashes executable/configuration/environment data; it is not a server-issued tenant identity. Mappings must match before source access or upload. Project selection checks project identity and unique name resolution.
- Upload/archive handling belongs to the CLI. Marx does not retry submissions. A stopped submission may already have been accepted remotely; without a scan ID, check Checkmarx One before retrying. Known IDs can be reconciled without resubmission. Remote cancellation requires a subsequent status check.
- At most eight scan jobs, ten ordinary CLI commands and two reserved cancellation commands run concurrently. The ordinary queue is bounded at 128 requests and desktop operations at 256, with at most eight arguments and 64 MiB combined raw input per operation and a shared 128 MiB raw input admission budget. Decoding and retained data have additional overhead. CLI stdout is capped at 64 MiB, stderr at 1 MiB and help at 512 KiB. Submissions time out after 30 minutes, reports after ten minutes and monitoring after 24 hours. Three unrecognized statuses stop monitoring as Unknown. Summary failures do not change a remotely completed scan to Failed.
- Reports use private temporary directories and are removed after reading. Source snippets are bounded at 8 MiB and use rooted filesystem access. Provenance capture is limited to 20,000 files, 16 MiB per file and 256 MiB total.
- The project picker loads up to 1,000 projects. Workspace discovery supports npm/Yarn patterns and pnpm block lists, with bounds on expansion, directories, entries, nesting and project count. Other build-system dependency graphs are not parsed. Per-package uploads omit files outside that folder; shared lockfiles may need a root scan. Batches contain at most 200 packages and run at concurrency 1–4.
- SQLite stores normalized findings, jobs, the latest 1,000 log lines per job, pinned evidence, notes and handoffs. Cleanup is explicit and retains unresolved jobs and referenced evidence. Data is not encrypted by Marx; Windows profile ACLs protect local files. On macOS the database and existing WAL/SHM files are restricted to owner read/write; nonregular database paths are rejected. Deletion is not secure erasure.
- Electron and earlier prototype databases are not migrated. Unsupported schema versions and corrupt databases are preserved and rejected. Restart and recovery of committed evidence from an interrupted WAL snapshot with an incomplete tail were tested. A real SQLite `SQLITE_FULL` error induced with a page limit rolled back the whole evidence transaction. Arbitrary damaged-page repair and exhaustion of the physical disk remain unqualified.

The native Go suite and acceptance-tagged desktop workflow ran with Go's race detector using a private portable LLVM-MinGW compiler; neither run reported a race. This supplements functional concurrency coverage and does not prove the absence of every possible race.

## CVE intelligence

Public intelligence is optional and applies only to explicit CVE IDs. It does not infer repository reachability, execute exploit references, replace scanner severity, validate a manual risk acceptance or establish a fixed finding. Sources can disagree or be unavailable; CISA absence is scoped to the fetched complete catalog, and missing EPSS stays unknown. A provider request reveals the requested CVE IDs and ordinary network metadata, even though repository and tenant details are excluded.

The intelligence workflow has macOS and Windows synthetic native acceptance, an explicit public-source smoke check, and focused Windows production interaction coverage recorded in [final acceptance](final-acceptance.md). Earlier dated evidence qualifies its recorded source revision only. Full production manual checks, live tenant compatibility and signing remain separate. See [the intelligence guide](cve-intelligence.md) for retention, limits and evidence semantics.
